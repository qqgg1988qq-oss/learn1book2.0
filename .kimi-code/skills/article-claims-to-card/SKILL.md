# article-claims-to-card: 文章观点 → 卡片

把一篇文章的作者观点快速提取出来，并铸成可渲染的结构化文案卡片。

---

## 使用方式

### 触发词

```
/article-claims-to-card
```

或自然语言：

```
把这篇文章的观点做成卡片
提取这篇文章的论点并做卡
帮我做一组观点卡片
```

### 输入

用户需要提供一篇文章，三选一：

1. **文件路径**（推荐）：`/path/to/article.md`
2. **网页链接**：提供 URL，若无法获取则请用户粘贴正文
3. **直接粘贴文本**：将文本保存为临时文件后处理

---

## 工作流

### 步骤 1：提取观点

调用项目内 Skill `/article-claims-extractor` 对原文进行观点提取。

- 生成文件：`{源文件名}-claims.md`
- 提取内容包括：核心论点、分论点、价值判断、因果判断、事实断言、隐含前提

### 步骤 2：格式化输出核心论点与分论点

读取生成的 `{源文件名}-claims.md`，只取 **核心论点** 和 **分论点** 两部分。

按以下格式在终端输出：

```
1.论点1:解释;2.论点2:解释;3.论点3:解释.....
```

格式规则：
- 仅保留「论点一句话」和「简要概括」
- 用 `1.论点:解释;2.论点:解释;` 的形式串联
- 数字后接论点原文，冒号后接简要概括，分号分隔不同条目
- 末尾可保留或省略分号

### 步骤 3：调用 xl-card 铸卡（仅核心论点）

从格式化观点清单中筛选出 **核心论点**，单独作为输入内容调用 `/xl-card`（默认使用 `-m` 多卡模式）。

- 每张卡片只对应一个核心论点，分论点不生成卡片
- xl-card 会先将 JSON 写入其默认目录：`/Users/chouchou/Documents/Obsidian Vault/九局下半怎么破局/概念卡片`
- **本 Skill 会将生成的 JSON 卡片复制到源文件所在目录**，确保输出位置与源文件一致
- 文件名从卡片内容自动提取

### 步骤 4：报告结果

向用户报告：
1. 观点提取文件路径
2. 格式化观点清单（已展示）
3. 复制到源文件目录的 JSON 卡片文件路径

## 输出示例

### 格式化观点清单

```
1.你不需要更多时间，你需要更多专注:人们常把低效归咎于动力或时间不足，真正缺的是把注意力收回到一件事上的能力;
2.专注是工作的力量乘数:真正产出来自把深度时间押在正确任务上，而非工作时长;
3.大脑是一台内存有限的电脑:杂念和未完成任务占用认知带宽，专注的前提是清理后台程序;
4.分心是挑战与技能没对齐的信号:焦虑说明任务太难，无聊说明任务太简单，应据此调整难度;
5.超专注需要一套可操作系统:由身份、项目、截止日期、时间块、杠杆任务、例行程序、休息共同支撑。
```

### 卡片输出

根据 xl-card 规则，仅对核心论点生成 JSON 文件，随后复制到源文件所在目录。每张卡片包含：
- `title`：观点一句话（≤20 字）
- `subtitle`：简要概括（≤30 字）
- `body`：3-5 段解释
- `items`：支撑依据或行动建议
- `footer.signature`：固定为「八零后阿力的觉醒日记」
- `footer.source`：从原文提取的作者/来源

---

## 注意事项

- 若原文是英文或其他语言，article-claims-extractor 会输出中文，本 Skill 全程使用中文。
- 核心论点与分论点之外的类型（价值判断、因果判断等）不参与格式化输出，但会保留在 `-claims.md` 中。
- xl-card 仅对核心论点生成 JSON 卡片，分论点只参与格式化文本输出。
- xl-card 先生成 JSON 到其默认目录，本 Skill 再将其复制到源文件同目录。
- 若 xl-card 生成多张卡片，会按 `卡{N}_{name}.json` 命名；复制到源目录时保留原文件名。
- 对于粘贴文本或网页链接，源目录指当前工作目录。
