# Broadcast Maker — 文章到口播文案一站式工作流

将任意文章通过 **深度精读 → 论据收集 → 询问时长 → APAG框架 → 论据库检索 → 人味口播转化 → 质量审计 → 文件输出** 八步流水线，自动生成可直接录制的视频文案。

## 工作流概览

```
用户输入文章
    ↓
[Step 1] Deep Read — 10维度深度精读分析
    ↓
生成结构化精读报告 → 保存为 {源文件名}-deep-read.md
    ↓
[Step 2] Evidence Collect — 从精读报告中提取论据并入库
    ↓
调用 evidence-collector 将概念/数据/案例/金句存入本地论据库
    ↓
[Step 3] Ask Duration — 询问视频时长
    ↓
[Step 4] APAG Outline — 生成文章框架 → 保存为 {源文件名}-apag-outline.md
    ↓
[Step 4.5] Evidence Query — 从论据库检索相关素材
    ↓
调用 evidence-query 查询与文章主题/痛点相关的高质量论据
    ↓
[Step 5] Human Script — 根据框架与检索到的论据写人味口播文案 → 保存为 {源文件名}-human-script.md
    ↓
[Step 6] Quality Audit — 纵向论证审计 + 横向衔接审计 + 归因核查，发现问题当场修复并记录
    ↓
产物均保存到源文件所在目录（或用户指定的输出目录）
```

## 使用方式

```
/broadcast-maker ./article.md
```

或直接在对话中粘贴文章内容并说"做成视频文案"。

## Step 1 — 深度精读（自动执行）

接收到文章后，立即按照 `deep-reader` 的标准进行10维度分析：

### 分析维度（必须全部覆盖）

1. **元信息** — 标题、作者、出处、类型、核心主题
2. **核心论点** — 中心论点与分论点、逻辑关系
3. **关键概念与定义** — 所有专业术语 + 通俗解释（比喻/类比）
4. **论据与证据** — 数据、案例、引用、修辞，标注论据→论点的支撑关系
5. **逻辑结构与推理链** — 总体结构、段落衔接、关键推理步骤
6. **方法论** — 研究方法、分析框架、优势与局限
7. **隐含知识与前提假设** — 默认背景知识、未经证明的前提、学术背景
8. **重要引用原文** — 3-10句核心原文 + 重要性标注
9. **知识网络与关联** — 外部领域关联、可延伸主题、理论概念
10. **批判性思考** — 论证薄弱环节、潜在反驳角度、知识边界

### 精读原则

- 不得因知识点"不重要"而跳过
- 多层次解析：字面 → 深层逻辑
- 关键概念必须附带通俗解释（比喻/类比）
- 输出必须完整，包含自检清单

## Step 2 — 论据收集（自动执行）

精读报告生成后，立即调用 `evidence-collector` 从报告中提取有价值的四类论据：

1. **概念** — 有解释力的理论、模型、方法论、定义
2. **数据** — 统计数字、调查比例、对比结果、趋势
3. **案例** — 具体人物、事件、故事、实验、企业经历
4. **金句** — 可直接引用的原话、观点、判断句

### 调用方式

- 以生成的 `{源文件名}-deep-read.md` 作为输入源
- 使用项目级 skill：`/Users/chouchou/Desktop/myProject/learn1book2.0/.kimi-code/skills/evidence-collector`
- 保存路径固定为：`/Users/chouchou/Documents/Obsidian Vault/九局下半怎么破局/参考资料/论据库/`

### 执行原则

- 自动完成去重与合并，避免重复入库
- 新论据按 `CONCEPT-XXXX` / `DATA-XXXX` / `CASE-XXXX` / `QUOTE-XXXX` 规则编号
- 同步更新论据库 `00-索引.md`
- 若报告内容已被部分收集过，以去重结果为准，不强制新增

### 用户可见

- 向用户简要报告本次入库结果（新增/合并/跳过数量）
- 不要求用户确认，作为 deep-reader 后的自动下游步骤

## Step 3 — 询问时长（自动执行）

精读和论据收集完成后，向用户确认视频时长：

| 选项 | 时长 | 适用场景 | 字数范围 |
|------|------|---------|---------|
| 短视频 | 1-2分钟 | 抖音/小红书/视频号快知识 | 300-500字 |
| 中视频 | 5-15分钟 | B站/YouTube标准知识视频 | 1200-3500字 |
| 长视频 | 15-40分钟 | B站深度/播客/讲座 | 3500-10000字 |

**默认**：若用户未明确选择，推荐中视频（5-15分钟）。

## Step 4 — APAG 框架生成（自动执行）

根据精读报告和用户选择的时长，调用 `apag-writing-outline` 生成 APAG 四段式文章框架，并保存为 `{源文件名}-apag-outline.md`。

### 框架内容

`apag-writing-outline` 会按以下结构输出可执行的写作大纲：

1. **Attention（钩子 / 标题）**：3-5 个候选钩子，并推荐最佳钩子
2. **Perspective（视角 / 问题）**：描绘观众当前的错误信念、痛苦与失败模式
3. **Advantage（优势 / 解决方案）**：核心观点、之前-之后对比、社会证明/权威引用、类比/隐喻
4. **Amplify/Gamify（放大 / 游戏化）**：3-5 个具体步骤、每个步骤的即时收益、降低行动摩擦的小技巧、明确 CTA

### 框架输出要求

- 框架必须写入文件，不能只在对话中展示
- 文件名为 `{源文件名}-apag-outline.md`
- 保存路径与精读报告相同（源文件所在目录或用户指定目录）
- 向用户报告框架文件保存路径，并附上核心摘要

### 时长对应的内容策略

- **短视频**：钩子候选 + 1 个核心论点/优势 + 1 个类比 + 1 个行动号召
- **中视频**：完整 APAG 四段，第二段 2-3 个错误信念/痛苦，第三段 2-4 个分论点/前后对比 + 2-3 个类比，第四段 3 个行动步骤
- **长视频**：完整 APAG 四段，第二段深入 3-4 个错误信念/失败模式，第三段覆盖 4-6 个分论点 + 3 个以上类比 + 批判性思考，第四段 4-5 个行动步骤

## Step 4.5 — 论据库检索（自动执行）

在生成人味口播文案前，先从本地论据库中检索与文章主题、APAG 框架中的痛点/关键词相关的高质量素材，为口播文案提供"弹药支撑"。

### 检索依据

基于以下信息构造查询主题：
- 文章核心主题（来自精读报告元信息）
- APAG 框架中匹配的痛点类型
- APAG 框架中的核心关键词（如"中年危机""注意力经济""即时通讯焦虑"等）
- 文章目标人群

### 调用方式

运行本地检索脚本：

```bash
python /Users/chouchou/Desktop/myProject/learn1book2.0/.kimi-code/skills/evidence-query/scripts/evidence_query.py "{查询主题}" --top 10 --min-quality 3
```

可针对 APAG 框架中的不同模块分别查询：
- **开头钩子**：`--scene "场景/开头吸引" --type 金句`
- **核心论据**：`--scene "场景/核心论据" --type 数据`
- **概念解释**：`--type 概念`
- **案例支撑**：`--type 案例`

### 筛选与使用原则

1. **优先高质量**：优先选用 quality ≥ 4 的论据，其次考虑 quality ≥ 3。
2. **宁缺毋滥**：如果检索结果与文章主题或 APAG 框架关联度低，直接弃用，不强行加入。
3. **自然化用**：不要直接搬运学术化表达，要将论据改写成口播语境下的"人话"。
4. **标注来源**：如果使用了论据库中的素材，在 `-human-script.md` 的制作建议或自检清单中简要标注参考了哪些条目。
5. **数量控制**：短视频融入 0-1 条，中视频融入 1-2 条，长视频融入 2-3 条。

### 输出

整理出 3-10 条相关论据清单，作为 Step 5 的输入之一。清单中每条包含：
- ID 和类型
- 标题
- 来源
- 质量分
- 核心内容摘要
- 建议在口播中的使用位置（开头 / 主体 / 结尾）

## Step 5 — 人味口播文案创作（自动执行）

根据 Step 4 生成的 APAG 框架、Step 4.5 检索到的论据库素材，以及用户选择的时长，调用 `content-to-human-script` 生成自然、有真人质感的口播文案，保存为 `{源文件名}-human-script.md`。

### 输入

- Step 4 生成的 `{源文件名}-apag-outline.md`
- Step 4.5 检索到的相关论据清单（来自本地论据库）
- 用户选择的视频时长

### 输出要求

- 严格按照 APAG 框架组织口播文案
- **按弧线写作，不按时间槽堆模块**：APAG 大纲里的时间分配（如"0:00-1:00 钩子+立论"）只是字数预算，不是段落边界。大纲把多个模块压进一个时间槽时，必须把它们展开成自然的推理流（悬念→论证→与观众的关系→主题预告），禁止把两个独立论点首尾相接、用"因为""所以"强行粘合
- **钩子必须落在文章主题上**：钩子结尾的最后一句话必须点明本期主题，让观众听完知道接下来听什么。如果核心论点有两半（如"努力被高估/判断力被低估"），必须说全，禁止只给半句就结束段落
- **归因必须核对原文**：引用的每句话，说话人必须与原文一致（如"决策正确率 80% vs 70%"是纳瓦尔的话，不能归给巴菲特）。不确定归属时回到 `-deep-read.md` 或原文核查，禁止凭印象归因
- **精英案例必须当场桥接**：使用超出普通人语境的例子（管十亿美元、硅谷投资人）时，同一段落内必须补一句"这跟普通观众有什么关系"，禁止让观众自己跨这道鸿沟
- **单一研究引用要审慎**：引用某项研究作为论据时，若该研究存在已知的方法论争议，用一句话带过（"后来也有人挑刺，但大方向成立"），不做盲目背书
- 在合适位置自然融入 0-3 条高质量论据，增强说服力与信息密度
- 注入真人特征：有观点、有节奏变化、有具体细节、承认复杂、适当使用"我"
- 规避 `content-to-human-script` 中列出的 24 种 AI 模式
- 使用纯中文表达，**严格禁止中英混用**。口播文案面向中文听众，所有内容都必须能用中文朗读出来
- 英文术语处理规范：
  - 普通英文概念必须译为中文，如 `niche down` → "垂直细分"/"收窄定位"，`creator economy` → "创作者经济"，`one trick pony` → "一招鲜"/"只会一招的人"
  - 人名、品牌名、平台名可保留原文，但前后必须是中文语境，如 "Dan Koe"、"YouTube"
  - 若原文金句是英文，必须先用中文完整表达其含义，再视情况补充英文原句；禁止在中文句子中直接插入英文短语
  - 错误示例："所有人都在跟我说 niche down，niche down，再 niche down" → 正确："所有人都在跟我说，要垂直细分，要垂直细分，再垂直细分"
  - 错误示例："People are craving human connection" → 正确："人们真正渴望的是真实的连接"
- 包含语气标注（停顿、语速变化、情绪提示等）
- 生成时进行自我评估，输出人味评分

### 时长对应的内容策略

- **短视频**：只保留最核心的 1 个论点 + 1 个类比 + 真实感受结尾；如论据高度契合，可在结尾点 1 条金句
- **中视频**：保留 2-3 个分论点 + 2 个类比 + 完整起承转合 + 个人观点；在 1-2 个分论点中自然融入数据/案例/金句
- **长视频**：覆盖 4-6 个分论点 + 3 个以上类比 + 完整结构 + 批判性思考 + 真实矛盾；在 2-3 个分论点中融入论据

### 语气标注

文案中需包含以下标注：

| 标记 | 含义 |
|------|------|
| （停顿） | 1-2秒沉默，制造节奏感 |
| （停顿0.5秒） | 短停顿，逗号级 |
| （笑） | 自然轻笑，增加亲和力 |
| （放慢语速） | 降低语速，增强氛围感 |
| （压低声音） | 降低音量，制造紧张/神秘感 |
| （提高语调） | 提高音调，表达意外/兴奋 |

## Step 6 — 质量审计（自动执行，不可跳过）

口播文案写入文件后、向用户汇报前，必须对 `-human-script.md` 全文做三遍审计，发现问题**当场修复并重新保存**，并在文末自检清单中记录每处修复。

### 第一遍：纵向论证审计（每个观点 → 有没有支撑）

逐节列出文案中的核心观点，逐一检查：

- 每个观点是否有论证链、案例或数据支撑？裸奔的观点必须补上论证或删掉
- 类比是否真的类比了同一个逻辑（例：方向盘偏差类比的是"微小差距随距离放大"，不能偷换成别的）
- 论证与论点是否错位（例：费曼三页纸论证的是"真懂=能讲清楚"，不能用来直接论证"要读原著"）

### 第二遍：横向衔接审计（每句话 → 跟前一句是什么关系）

这是最容易被跳过、也最容易出问题的一遍。逐段检查：

- **段落结尾句与下段开头句是什么关系**：弧线是否已收拢？禁止在过渡句/落地句之后再追加一个新论点然后悬停（金句要收弧，不做补记）
- **每个连接词是否真实成立**：逐一检查"因为/所以/但/紧接着/也就是说"——"因为"后面必须真是原因，"所以"后面必须真是推论。连接词不成立时改写句子，禁止用连接词当胶水掩盖模块堆叠
- **设问不重复**：刚回答过的问题，下一段不得再次设问
- **论点说全**：两半结构的论点（努力/判断力、短期痛苦/长期收益）不得只给半句收尾
- **朗读者视角**：以"第一次听的观众"视角通读，任何需要观众自己补的跳跃都要当场补平

### 第三遍：归因与证据核查（每个引用 → 归错人没有、说过头没有）

- 逐条核对文案中的引用（原话、数据、研究），说话人/来源必须与 `-deep-read.md` 和原文一致
- 检查是否把作者的观点写成了旁白断言（"纳瓦尔说 X"和"事实就是 X"要分清）
- 检查研究引用是否缺必要的审慎说明
- 检查钩子与正文、正文与 APAG 大纲之间是否有口径不一致（如大纲归因错误要一并修正）

### 审计记录格式

在 `-human-script.md` 自检清单末尾追加：

```markdown
- [x] 质量审计（{日期}）：{修复点1}；{修复点2}；{修复点3}
```

审计未发现问题的，记录 `- [x] 质量审计（{日期}）：三遍审计通过，未发现问题`。禁止省略这一步。

3. 关键概念与定义（含通俗类比）
4. 论据与证据
5. 逻辑结构与推理链
6. 方法论分析
7. 隐含知识与前提假设
8. 重要引用原文
9. 知识网络与关联
10. 批判性思考
11. 自检清单

### APAG 框架文件内容

输出的 `-apag-outline.md` 包含：
1. 文章元信息（标题、作者、来源）
2. Attention（钩子 / 标题）：3-5 个候选钩子 + 最佳推荐
3. Perspective（视角 / 问题）：错误信念、痛苦、失败模式、场景化描写
4. Advantage（优势 / 解决方案）：核心观点、之前-之后对比、社会证明、类比/隐喻
5. Amplify/Gamify（行动阶梯 / 行动号召）：3-5 个具体步骤 + 明确 CTA
6. 时长建议与内容取舍

### 人味口播文案文件内容

输出的 `-human-script.md` 包含：
1. 文章元信息（标题、作者、来源）
2. 视频时长与字数预估
3. APAG 四段式完整人味口播文案（含语气标注）
   - 开头钩子（0:00-0:30）
   - 主体分节展开
   - 结尾引导
4. 引用的论据库素材说明（使用了哪些论据、用在哪个位置、如何化用）
5. 视频制作建议（可选画面素材、字幕重点、BGM建议）
6. 人味评分
7. 自检清单（重点检查是否有中英文混用、是否规避 24 种 AI 模式、是否有真人质感、论据是否自然融入、是否通过 Step 6 三遍质量审计并记录修复点。中英文混用检查：通读全文，凡出现中文句子中插入英文单词/短语的情况，必须翻译或改写为纯中文表达。）

## 注意事项

- 精读报告、APAG 框架、口播文案三个文件默认都保存到源文件所在目录
- 精读报告生成后，会自动调用 `evidence-collector` 收集论据并入库，无需用户额外操作
- APAG 框架生成后，会自动调用 `evidence-query` 从本地论据库检索相关素材，作为人味口播文案的输入
- `evidence-query` 检索结果不单独生成文件，但会在 `-human-script.md` 中体现使用了哪些论据
- 只有用户明确要求或源目录不可写时，才保存到 Obsidian 博客目录
- 若用户要求调整（增删故事、改变语气、调整时长），直接修改对应阶段的产物并重新保存
- 口播文案完成后必须执行 Step 6 质量审计（纵向论证 / 横向衔接 / 归因核查三遍），这是固定环节，不因赶时间或文案"看起来没问题"而跳过
- 保留 `deep-reader`、`evidence-collector`、`evidence-query`、`apag-writing-outline` 和 `content-to-human-script` 各自的核心能力，不简化任何分析维度
- 如果论据库中缺少与文章主题相关的高质量素材，以文章本身的观点和 APAG 框架为主，不强行插入低相关度论据
- **严格避免中英混用**：原文为英文时，必须将其核心含义翻译为中文后再写入口播文案；禁止直接保留英文短语在中文句子中，如"所有人都在说 niche down"必须改为"所有人都在说垂直细分"
